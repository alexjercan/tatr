# Add a Windows tatr.exe build

- STATUS: CLOSED
- PRIORITY: 85
- TAGS: feature,build,windows

## Flow State

- FLOW STEP: DONE

## Story

As a Windows user, I want the project to produce a native `tatr.exe`, so I can
run tatr from Windows without building the Unix binary myself.

Done means the repository has a documented, repeatable build path that creates a
Windows PE executable named `tatr.exe`; the normal Unix build and test path keeps
working; and the compatibility choices are recorded so future work does not
accidentally regress the Windows target.

## Steps

- [x] Add small platform shims in `tatr.c`/`aids.h` for the POSIX calls that
      differ under MinGW, starting from the actual compile errors and keeping
      the Unix code path unchanged.
- [x] Add a Windows cross-build target to `Makefile` that emits
      `dist/tatr.exe` using the MinGW compiler and keeps `make`, `make clean`,
      and `make install` behavior unchanged for Unix users.
- [x] Extend `flake.nix` so `nix develop` provides the MinGW cross compiler and
      exposes a package or app path that can build the Windows artifact
      reproducibly from Linux.
- [x] Add an integration-style checker test or script target that exercises the
      Windows build path and verifies the output is a PE executable named
      `tatr.exe`.
- [x] Document the Windows build and artifact location in `README.md` and update
      `AGENTS.md` if the canonical build guidance changes.
- [x] Run the full Unix test suite, memcheck suite, Windows artifact check, and
      tatr conformance checks.

## Definition of Done

- `nix develop -c make windows` produces `dist/tatr.exe`
  (cmd: `nix develop -c make windows`).
- The produced artifact is a Windows PE executable, not an ELF binary
  (cmd: `file dist/tatr.exe | grep -E "PE32|PE32\\+"`).
- The normal Unix build still produces `./tatr`
  (cmd: `nix develop -c make`).
- The integration suite covers the Windows build path
  (cmd: `rg -n "tatr\\.exe|make windows|PE32" checker.sh README.md Makefile flake.nix`).
- The full test suite passes
  (cmd: `nix develop -c ./checker.sh`).
- The memcheck suite passes for the Unix binary
  (cmd: `nix develop -c ./checker.sh --memcheck`).
- tatr conformance passes
  (cmd: `./tatr check` and `./tatr check --ledger LESSONS.md`).

## Work Notes

- Added a MinGW-backed `make windows` target that writes `dist/tatr.exe` while
  leaving `make`, `make install`, and the Unix `./tatr` output unchanged.
- Added `packages.windows` to the flake and put the MinGW cross compiler plus
  `file` in the dev shell so the Windows build and checker proof are
  reproducible from Linux.
- Added a checker integration test that runs `make windows` and verifies the
  output with `file` as a PE executable.
- Added small Windows portability shims in `aids.h`: a cross-platform mkdir
  wrapper, separator handling for `/` and `\`, drive-prefix-aware recursive
  directory creation, and `getcwd` slash normalization.
- Documented the Windows build path in `README.md` and `AGENTS.md`.
- Added `/dist` and `/result` to `.gitignore` because both are generated by the
  Windows/Nix build proofs.

## Verification

- `nix develop -c make windows` initially failed with `No rule to make target
  'windows'`, then passed after the Makefile/Nix changes.
- `nix develop -c make` passed and produced `./tatr`.
- `nix develop -c make windows` passed and produced `dist/tatr.exe`.
- `file dist/tatr.exe` reported `PE32+ executable for MS Windows 5.02
  (console), x86-64`.
- `nix build .#windows` passed; `file result/bin/tatr.exe` reported a PE32+
  Windows console executable.
- `rg -n "tatr\\.exe|make windows|PE32" checker.sh README.md Makefile flake.nix`
  found the checker, docs, Makefile, and flake coverage.
- `nix develop -c ./checker.sh` passed 70/70 tests.
- `nix develop -c ./checker.sh --memcheck` passed 70/70 tests.

## Close-out

- What changed: tatr can now be cross-built to a native Windows console
  executable with `nix develop -c make windows`; the flake also exposes
  `nix build .#windows`, and the docs describe both paths.
- Why: a real PE `tatr.exe` is the requested artifact. Renaming the Unix ELF
  binary or starting with an installer would not satisfy the run-on-Windows
  requirement.
- Difficulty: the direct MinGW probe found the first actual portability error:
  MinGW's `mkdir` takes one argument. While fixing it, I also normalized
  separator handling and drive prefixes so the file helpers do not assume Unix
  paths when compiled for Windows.
- Self-reflection: the red `make windows` check was useful because it kept the
  task focused on a concrete artifact. Next time, add ignore rules for generated
  build artifacts at the same time as the build target to avoid an avoidable
  dirty-worktree pass.
